# Отчёт о лабораторной работе № 1

## Создание проекта Next.js с использованием React, TypeScript и App Router

## 1. Цель работы

Цель работы — получить практические навыки создания веб-приложения на основе Next.js и React, использования TypeScript для типизации компонентов, организации маршрутизации средствами App Router, настройки метаданных и глобальных стилей, а также проверки качества проекта с помощью ESLint и производственной сборки.

## 2. Концепция приложения

В ходе выполнения лабораторной работы была разработана начальная версия учебного приложения **QuestCity**. Приложение задумано как агрегатор городских квестов, объединяющий сведения о предложениях разных организаторов в одном интерфейсе. На первом этапе реализован информационный каркас проекта: главная страница, страница «О проекте», навигация и представление трёх будущих возможностей сервиса.

### 2.1. Решаемая проблема

Информация о городских квестах часто распределена между сайтами отдельных организаторов. Из-за этого пользователю приходится самостоятельно искать площадки, открывать несколько ресурсов и сравнивать жанры, стоимость, сложность, продолжительность, число игроков и другие характеристики. QuestCity должен сократить количество таких действий: собрать предложения в одном веб-приложении и предоставить понятный интерфейс для поиска и выбора подходящего варианта.

### 2.2. Целевая аудитория

Целевая аудитория приложения — жители города и туристы, заинтересованные в посещении квестов. Сервис ориентирован на компании друзей, пары, семьи и отдельных пользователей, которые хотят выбрать развлечение с учётом интересующих характеристик.

### 2.3. Основная предметная сущность

Главной предметной сущностью приложения является **квест**. В последующих версиях с этой сущностью могут быть связаны название, описание, изображения, жанр, адрес, организатор, допустимое количество игроков, продолжительность, уровни сложности и страха, возрастное ограничение, цена, рейтинг, отзывы и доступные сеансы. В рамках лабораторной работы № 1 полноценная модель данных не создавалась.

Первоначальная концепция предусматривает следующие пользовательские возможности:

1. просмотр каталога городских квестов;
2. поиск и подбор квестов по характеристикам;
3. сохранение интересных квестов в избранное.

Дальнейшее развитие проекта предполагает создание каталога, динамических страниц отдельных квестов, поиска, фильтрации, отзывов, бронирования, учётных записей и личного кабинета. Перечисленная функциональность относится к будущим лабораторным работам и в текущей версии не реализована.

## 5. Разработка переиспользуемого компонента

Для отображения предполагаемых возможностей сервиса был создан компонент `FeatureCard`. Его свойства описаны типом `FeatureCardProps` и обёрнуты в `Readonly`. Компонент принимает обязательные строковые свойства `title` и `description`, благодаря чему TypeScript проверяет корректность его использования. Семантический элемент `article` позволяет воспринимать каждую карточку как самостоятельный информационный блок.

Листинг 1 содержит код компонента `FeatureCard`.

```tsx
type FeatureCardProps = Readonly<{
  title: string;
  description: string;
}>;

export default function FeatureCard({
  title,
  description,
}: FeatureCardProps) {
  return (
    <article className="feature-card">
      <span className="feature-card__marker" aria-hidden="true" />
      <h3>{title}</h3>
      <p>{description}</p>
    </article>
  );
}
```

## 6. Реализация главной страницы

Главная страница оформлена как первый экран городского сервиса развлечений. В верхней части размещены название QuestCity и ссылка на страницу «О проекте». Основной блок объясняет проблему разрозненной информации о квестах, назначение агрегатора и его целевую аудиторию. Далее расположен раздел «Возможности», в котором компонент `FeatureCard` используется три раза для представления каталога, поиска и избранного. Информационный блок в нижней части дополнительно поясняет назначение приложения.

Для структуры страницы использованы семантические элементы `main`, `section`, `header`, `nav`, `aside`, `article` и `footer`. Переход на маршрут `/about` реализован компонентом `Link` из пакета `next/link`. Страница остаётся серверным компонентом, поскольку клиентское состояние и обработчики событий для требований первой лабораторной работы не нужны.

## 8. Проверка приложения

После завершения реализации в каталоге `app` была выполнена статическая проверка командой:

```bash
npm run lint
```

Команда завершилась успешно, ошибок ESLint обнаружено не было. Затем была запущена производственная сборка:

```bash
npm run build
```

Сборка завершилась успешно. Next.js скомпилировал проект, выполнил проверку TypeScript и статически сформировал маршруты `/` и `/about`.
